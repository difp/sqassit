# 🏸 Squash-Bot — Telegram Web App для сквош-тренировок

Монолитный бэкенд на **FastAPI + aiogram 3** с легковесным Web App
(**Jinja2 + TailwindCSS**, без Node.js). База — **SQLite** в изолированном
volume. Контейнер собран по принципу наименьших привилегий.

```
squash-bot/
├── app/
│   ├── main.py          # FastAPI + подключение aiogram (Web App API, страницы)
│   ├── bot.py           # aiogram-хендлеры и планировщик напоминаний
│   ├── database.py      # SQLite (aiosqlite), только параметризованные запросы
│   ├── secure_auth.py   # HMAC-SHA256 валидация Telegram initData
│   ├── config.py        # настройки строго из переменных окружения
│   └── templates/        # base.html, index.html (игрок), coach.html (тренер)
├── data/                # том для squash.db (переживает пересборку образа)
├── docs/
│   ├── COACHES.md       # роли, заявки, тренеры
│   └── DEPLOY.md        # пошаговый деплой (в т.ч. без сервера, туннель)
├── requirements.txt     # версии строго зафиксированы
├── Dockerfile
├── docker-compose.yml
├── Makefile             # операционные команды (up/logs/backup/release)
├── VERSION / CHANGELOG.md
├── .env.example
└── .dockerignore / .gitignore
```

## 1. Быстрый старт

```bash
# 1. Секреты
cp .env.example .env
# откройте .env и заполните BOT_TOKEN и COACH_TELEGRAM_ID

# 2. Папка данных (UID контейнера = 1000)
mkdir -p ./data && sudo chown -R 1000:1000 ./data

# 3. Запуск
docker compose up -d --build
docker compose logs -f          # логи в stdout
```

Приложение поднимется на `http://127.0.0.1:8000` (`/` — игрок, `/coach` — тренер).
Для реального Telegram Web App обязателен **HTTPS** — поставьте reverse-proxy
(nginx/caddy) и укажите его адрес в `WEBHOOK_BASE_URL`.

📘 Пошаговый деплой (в т.ч. на Raspberry Pi/мини-ПК и как получить HTTPS без
сервера через туннель): [`docs/DEPLOY.md`](docs/DEPLOY.md).

### Как добавить тренеров

`COACH_TELEGRAM_ID` в `.env` — это **владелец** (главный тренер) и менеджер клуба.
Тренеров может быть **сколько угодно**:

* **Заявка** — вкладка «Тренер» видна всем; обычный пользователь оставляет заявку,
  владелец (или тренер с правами менеджера) одобряет её в разделе «Заявки» либо
  кнопкой в боте.
* **Вручную** — владелец/менеджер добавляет в разделе «Тренеры» по `telegram_id`
  или `@username` (тот должен был запускать бота).

Каждый тренер редактирует **только свои** занятия; чужие видит в разделе
**«Клуб»** (только чтение) и может **передать** своё занятие другому тренеру.
Подробно: [`docs/COACHES.md`](docs/COACHES.md).

### Режимы доставки апдейтов

* `BOT_MODE=polling` (по умолчанию) — не требует публичного адреса, удобно локально.
* `BOT_MODE=webhook` — укажите `WEBHOOK_BASE_URL` и случайный `WEBHOOK_SECRET`.
  Вебхук принимается на `POST /telegram/webhook` и проверяет заголовок
  `X-Telegram-Bot-Api-Secret-Token`.

## 2. Как работает

* **Тренер** (`/coach`): создаёт тренировку (дата, время, тип, лимит мест,
  длительность 60 мин), управляет напоминанием (по умолчанию за **270 мин = 4.5 ч**,
  есть тумблер и смещение), ведёт CRM-заметки по игрокам.
* **Игрок** (`/`): сетка на 7 дней вперёд, аватарки записавшихся (без username),
  запись в один тап, личный тумблер пуш-уведомлений.
* **Лист ожидания** — FIFO: при заполнении мест игрок попадает в очередь, а при
  отмене автоматически повышается первый ожидающий.
* **Правило отмены** — самостоятельная отмена запрещена, если до старта **< 4.5 ч**.
* **CRM** — карточка создаётся при `/start`, хранит `telegram_id`, `username`,
  `first_name` и `file_id` аватарки (сам файл **не пишется на диск** — отдаётся
  прокси-эндпоинтом `/api/avatar/{id}` с коротким in-memory кэшем).
* **Напоминание** задаётся в часах и минутах (в UI) и хранится как смещение в
  минутах; по умолчанию 4 ч 30 мин (270 мин). Есть быстрые пресеты.
* **История и корзина** — у тренера три раздела: «Активные» (предстоящие),
  «История» (прошедшие, с посещаемостью) и «Корзина» (удалённые с возможностью
  восстановления).
* **Уровень игры.** У каждой тренировки есть уровень (тренер выбирает в форме из
  справочника: «Новичок», «Начинающий», «Уверенный любитель»); отображается
  бейджем в карточке. Пустое значение = «не указан». Значения валидируются на
  сервере (`GET /api/levels`).
* **Профиль тренера.** В карточке тренировки у игрока видны тренер (аватар + имя) и
  краткое описание («о себе»). Тренер редактирует описание на своей вкладке.
* **Личное сообщение тренеру.** Тап по блоку тренера → «Написать» открывает форму.
  Сообщение сохраняется в БД и уходит тренеру в чат с ботом (фоновой доставкой —
  недоступность Telegram не блокирует игрока). Тренер может ответить прямо из бота:
  inline-кнопкой **«Ответить»** под сообщением (бот попросит текст, `/cancel` — отмена)
  либо командой `/reply <id> текст`; входящие — `/inbox`. Ответ приходит игроку в бот.
* **Добавление в календарь.** В карточке тренировки есть кнопка «Добавить в
  календарь» (на всю ширину): она открывает
  выбор — скачать `.ics` (Apple / Android / Outlook) или открыть Google Календарь.
  `.ics` генерируется на сервере (RFC 5545, UTC, напоминание за 30 мин) и отдаётся
  по `GET /calendar/{id}.ics`; авторизация — тем же подписанным `initData`, но
  через query-параметр (для обычной ссылки-скачивания).

### Защита от человеческих ошибок

* **Мягкое удаление тренировок.** DELETE не стирает данные, а помечает
  `deleted_at`. Тренировка и все записи сохраняются и восстанавливаются одной
  кнопкой (кнопка «Вернуть» прямо в тосте сразу после удаления). Безвозвратная
  очистка доступна только из корзины и требует подтверждения.
* **Защита от дублей.** Повторная отправка формы (двойной тап, ретрай при
  плохой сети) при совпадении времени и типа не создаёт вторую тренировку —
  сервер отвечает `409`, клиент спрашивает подтверждение и только тогда создаёт.
* **Возврат случайно снятого игрока.** Тренер видит всех участников, включая
  отменённых, и может вернуть любого (в место или в очередь по FIFO).
* **Правило 4.5 ч.** Самостоятельная отмена записи игроком блокируется за
  4.5 часа до старта; тренер при этом может снять/вернуть игрока.
* **Подтверждения** перед удалением тренировки с записанными и перед
  безвозвратной очисткой.

### Мобильный интерфейс

UI спроектирован в первую очередь под смартфон:

* полноэкранный app-shell с **нижней таб-навигацией** (thumb-зона), вкладка
  «Тренер» скрывается для игроков;
* **нативные темы Telegram** (`--tg-theme-*`) — автоматически светлая/тёмная;
* тап-таргеты ≥ 44px, учёт `safe-area-inset` (вырезы/жесты iPhone);
* **стек аватарок** с инициалами-фолбэком, вертикальная лента по дням со
  «липкими» заголовками «Сегодня/Завтра»;
* у тренера — **FAB** «＋» и **bottom-sheet** с формой, полосы заполнения мест;
* haptic-отклик (`Telegram HapticFeedback`) на ключевых действиях.

## 3. Обновление без потери данных
База лежит в `./data/squash.db` и смонтирована как volume, поэтому:

```bash
git pull                        # новый код
docker compose up -d --build    # пересборка образа
```

Файл БД остаётся нетронутым. Схема создаётся идемпотентно (`CREATE TABLE IF NOT EXISTS`).

## 4. Контур безопасности (чек-лист)

| Требование | Реализация |
|---|---|
| Наименьшие привилегии | `USER appuser` (UID 1000), `read_only: true`, `no-new-privileges`, `tmpfs /tmp`, нет `docker.sock` и корневых монтирований |
| Защита от SQL-инъекций | SQLite + `aiosqlite`, **все** запросы параметризованы (`?`); склейки строк нет |
| Безопасность Web App | `app/secure_auth.py`: HMAC-SHA256 (`secret = HMAC("WebAppData", bot_token)`) + `hmac.compare_digest` + проверка `auth_date` (анти-replay) |
| Supply chain | только официальные библиотеки, версии зафиксированы в `requirements.txt`; нет `os.system`/`subprocess`/внешних shell-скриптов |
| Секреты | только из env (`.env`), исключены из образа (`.dockerignore`) и из git (`.gitignore`) |

Дополнительно: любой эндпоинт API требует валидный `X-Init-Data`; панель тренера
дополнительно проверяет роль (`require_coach`); Telegram-токен не утекает в
браузер — аватарки отдаются через бэкенд-прокси.

## 5. Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен бота от @BotFather |
| `COACH_TELEGRAM_ID` | да | telegram_id **владельца** (главного тренера); он управляет списком тренеров |
| `TIMEZONE` | нет | часовой пояс (по умолчанию `Europe/Moscow`) |
| `DB_PATH` | нет | путь к БД (по умолчанию `/app/data/squash.db`) |
| `BOT_MODE` | нет | `polling` (по умолч.) или `webhook` |
| `WEBHOOK_BASE_URL` | для webhook | публичный HTTPS-адрес |
| `WEBHOOK_SECRET` | для webhook | секрет заголовка вебхука |
| `ALLOW_DEV_INIT_DATA` | нет | `false` в проде. `true` — превью Web App вне Telegram (dev) |

## 6. Релиз и эксплуатация

**Чек-лист перед запуском** (`make release`):

1. Заполнить `.env` (`BOT_TOKEN`, `COACH_TELEGRAM_ID`), убедиться, что
   `ALLOW_DEV_INIT_DATA=false`.
2. Настроить HTTPS reverse-proxy (nginx/caddy). При `BOT_MODE=webhook` задать
   `WEBHOOK_BASE_URL` и случайный `WEBHOOK_SECRET`.
3. `mkdir -p ./data && sudo chown -R 1000:1000 ./data`.
4. `make up` → `make ps` (контейнер `healthy`).
5. Открыть бота, `/start`, проверить расписание, запись и «Добавить в календарь».
6. Поставить регулярный бэкап (`make backup` по cron).

**Полезные команды** (`make help`):

```bash
make up        # собрать и запустить
make logs      # логи (stdout Docker)
make ps        # статус и health
make backup    # hot-бэкап SQLite в ./data/backup-<дата>.db
make down      # остановить (данные в ./data сохраняются)
```

**Мониторинг:** `GET /healthz` (используется `HEALTHCHECK`). Логи — в stdout
Docker с ротацией (10 МБ × 3). Один воркер: внутри процесса живут long-polling и
in-memory-состояние.

**Восстановление из бэкапа:** остановите контейнер, положите нужный
`backup-*.db` как `./data/squash.db` (при наличии удалите `squash.db-wal`/
`squash.db-shm`), запустите `make up`.

## 7. Локальная разработка (без Docker)

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
mkdir -p ./data
DB_PATH=./data/squash.db ALLOW_DEV_INIT_DATA=true uvicorn app.main:app --reload
```

> Локально Web App откроется только внутри клиента Telegram: `initData`
> подписывается Telegram, поэтому API без него вернёт `401`. Для превью в обычном
> браузере включите `ALLOW_DEV_INIT_DATA=true` и передайте подписанный `initData`
> в `?initData=...` (подпись всё равно проверяется на сервере).
