# Тренеры, роли и заявки

Система поддерживает **1 и более тренеров**. Тренер управляет своими занятиями и занятиями, где он назначен соавтором.

## 1. Роли

| Роль | Как получается | Возможности |
|---|---|---|
| **Администратор** (`COACH_TELEGRAM_ID`, в коде `is_owner`) | env `COACH_TELEGRAM_ID` | всё, что тренер, + заявки, реестр, выдача прав менеджера, передача любых занятий |
| **Менеджер** | тренер, которому администратор выдал права | заявки, реестр тренеров |
| **Тренер** | заявка одобрена (администратором/менеджером) или добавлен вручную | свои занятия и занятия, где он соавтор |
| **Пользователь** | любой вошедший в Web App | расписание, запись, календарь, **заявка в тренеры** |

Роль хранится в БД (таблица `coaches`), а не в одном id — поэтому тренеров может
быть сколько угодно. Администратор автоматически добавляется в реестр при старте.

## 2. Вкладка «Тренер» и заявка

Вкладка «Тренер» видна **всем**. Если пользователь не тренер — он видит форму
**«Стать тренером»**: описание и кнопку «Отправить заявку». После отправки
показывается статус (ожидает / одобрено / отклонено).

Заявку рассматривает **администратор** или **тренер с правами менеджера**:
- в Web App: раздел **«Заявки в тренеры»** → «Одобрить» / «Отклонить»;
- в боте: администратору и менеджерам приходит уведомление с кнопками «✅ Одобрить» / «❌ Отклонить».

При одобрении пользователь получает роль тренера и вкладку «Тренер».

## 3. Добавить тренера вручную (администратор/менеджер)

Вкладка «Тренер» → раздел **«Тренеры»** → введите `telegram_id` или `@username`
(пользователь должен был запускать бота, `/start`) → **«Добавить»**. Снять роль —
кнопкой «Снять» (администратора снять нельзя).

## 4. Права менеджера

Администратор в списке «Тренеры» включает тумблер **«менеджер»** у тренера. Менеджер
может рассматривать заявки и вести реестр. Администратор снять/выдать права
менеджера может только он сам.

## 5. Изоляция занятий

* **Активные** — свои занятия и занятия, где тренер добавлен соавтором.
* **История** — прошедшие свои занятия и занятия с соавторством.
* **Корзина** — удалённые занятия, созданные тренером.
* Права на отдельные действия определяются ролью автора или соавтора.

## 6. Серия тренировок по дням

В форме создания выберите **«По дням»**, укажите период, дни недели (например,
Пн / Ср / Пт) и время. Приложение создаст занятие на каждую подходящую дату.
Уже существующие занятия и прошедшие даты пропускаются — повторное нажатие
не создаёт дубли.

## 7. Передача занятия другому тренеру

На своей карточке — кнопка **➡ «Передать»**. Откроется список тренеров; выберите
получателя. После передачи занятие переходит в его «Активные», а у вас пропадает.
Передавать может **автор занятия** или **администратор бота**.

`POST /api/coach/trainings/{id}/transfer` `{"telegram_id": 777}`

## 8. API (кратко)

```
POST   /api/coach/apply                              # заявка (любой пользователь)
GET    /api/coach/apply                              # статус своей заявки
GET    /api/coach/applications                       # менеджер
POST   /api/coach/applications/{id}/approve|reject   # менеджер
GET    /api/coach/coaches                            # любой тренер
POST   /api/coach/coaches                            # менеджер
DELETE /api/coach/coaches/{id}                       # менеджер
PATCH  /api/coach/coaches/{id}/manager               # администратор
POST   /api/coach/trainings/batch                    # серия по дням недели
GET    /api/coach/club/trainings                     # любой тренер (чтение)
POST   /api/coach/trainings/{id}/transfer            # автор занятия/администратор
```

## 9. Безопасность

Личность подтверждается подписью `initData` (HMAC-SHA256 с токеном бота). Роль и
права проверяются на сервере по реестру `coaches`; операции с занятием ограничены
его автором. Заявки и реестр доступны только администратору/менеджеру.
