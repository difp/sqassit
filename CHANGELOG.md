## [Unreleased]

### Безопасность
- **Критично:** `/telegram/webhook` больше не принимает апдейты в `polling`-режиме.
  В `webhook`-режиме `WEBHOOK_SECRET` обязателен (≥32 символов, без placeholder),
  сравнение — в постоянном времени. Убран небезопасный placeholder из `.env.example`.
- Аватарки и `.ics` авторизуются узкими HMAC-токенами с TTL вместо полного
  `initData` в URL. Полный `initData` в query для `.ics` разрешён только при
  `ALLOW_DEV_INIT_DATA=true`.
- Обновлены зависимости с известными уязвимостями: aiogram, FastAPI, Starlette,
  aiohttp, Jinja2, python-dotenv, pydantic.

### Исправлено
- Повторный `POST /api/trainings/{id}/book` (двойной тап/retry) больше не
  переводит записанного игрока в лист ожидания и не меняет позицию в очереди.

## [1.2.0] — 2026-10-09

### Добавлено
- **Заявка в тренеры.** Вкладка «Тренер» теперь видна **всем**; обычный
  пользователь оставляет заявку, а владелец или тренер с правами **менеджера**
  одобряет/отклоняет её (в Web App и кнопками в боте). После одобрения
  пользователь получает роль тренера.
- **Права менеджера** (`coaches.is_manager`): рассматривать заявки и вести реестр;
  выдаёт/снимает только владелец.
- **Режим «Клуб»** — предстоящие занятия других тренеров в режиме только чтения
  (карточка и участники без действий).
- **Передача занятия** другому тренеру (автор занятия или владелец бота).
  `POST /api/coach/trainings/{id}/transfer`.

### Изменено
- Реестр тренеров (`GET /api/coach/coaches`) доступен любому тренеру (для передачи);
  управление (добавить/снять/права) — владелец или менеджер.
- Чтение участников занятия доступно любому тренеру; изменение — только автору.

## [1.1.0] — 2026-10-09

### Добавлено
- **Мульти-тренер (1+).** Роли хранятся в БД (таблица `coaches`). `COACH_TELEGRAM_ID`
  теперь **владелец**: управляет реестром тренеров из раздела «Тренеры» (добавить
  по `telegram_id`/`@username`, снять роль).
- **Изоляция занятий:** каждый тренер видит и редактирует только свои тренировки
  (`created_by`). Чужое занятие → `404`. Дубли-гард и корзина — в пределах своих.
- Карточка игрока показывает **тренера-автора** занятия; личное сообщение уходит
  именно ему (по `training_id`), а не общему аккаунту.
- Документация `docs/COACHES.md`; раздел «Тренеры» на панели (только владелец).

### Изменено
- Проверка роли в API и боте — по реестру `coaches`, а не по одному id.
- `/inbox` показывает сообщения, адресованные текущему тренеру.
- Уведомление новому тренеру и доставка сообщений — фоном (не блокируют ответ).

## [1.0.0] — 2026-10-09

Первый релиз Telegram Web App для сквош-тренировок.

### Добавлено
- Монолитный бэкенд **FastAPI + aiogram 3**, отдаёт Web App (Jinja2 + TailwindCSS) и API.
- Режим игрока: расписание на 7 дней, запись в один тап, стек аватарок участников,
  персональный тумблер пуш-уведомлений.
- Режим тренера: создание тренировок, уровень игры, напоминание в часах/минутах,
  полосы заполнения мест, список участников, CRM-заметки.
- Лист ожидания FIFO с автоповышением при отмене.
- Правило отмены: игрок не может выйти менее чем за 4.5 ч до старта (и после старта).
- Напоминания: фоновый планировщик, по умолчанию за 4.5 ч, тумблер и смещение.
- **История и корзина**: мягкое удаление тренировок, восстановление, безвозвратная
  очистка только из корзины, undo-тост.
- **Профиль тренера** (краткое описание) и **личные сообщения игрока тренеру через бота**
  с inline-кнопкой «Ответить», командами `/inbox` и `/reply`.
- **Экспорт в календарь**: `.ics` (RFC 5545, UTC, напоминание за 30 мин) и Google Календарь.
- Защита от человеческих ошибок: дубли-гард (`409` + `force`), возврат снятого игрока,
  подтверждения перед удалением.
- Мобильный UI: нижняя навигация, темы Telegram, safe-area, haptic-отклик, bottom-sheet, FAB.

### Безопасность
- HMAC-SHA256 валидация Telegram `initData` (сравнение в постоянном времени, анти-replay).
- SQLite (aiosqlite), только параметризованные запросы.
- Контейнер: непривилегированный пользователь (UID 1000), read-only ФС, `no-new-privileges`,
  `tmpfs /tmp`, нет доступа к хосту.
- Секреты только из окружения; `.env` исключён из образа и git.
- Версии зависимостей зафиксированы; отсутствуют `os.system`/`subprocess`/shell-скрипты.
- Аватарки отдаются бэкенд-прокси (токен не утекает в браузер), кэш в памяти.
- `ALLOW_DEV_INIT_DATA` (по умолчанию `false`) — послабление только для локальной разработки.

### Изменено
- Напоминание задаётся в часах и минутах; уровень игры вынесен в мета-строку карточки.
- Кнопка календаря — полноширинная, элементы карточки выровнены по правому краю.

### Инфраструктура
- Идемпотентные миграции SQLite (правило бесшовного обновления).
- `HEALTHCHECK` в образе и `docker-compose`, ротация логов, `stop_grace_period`.
- `Makefile` (build/up/logs/backup/release), `VERSION`, этот changelog.
