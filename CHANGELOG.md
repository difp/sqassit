# Changelog

Все значимые изменения проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [SemVer](https://semver.org/lang/ru/).

## [1.5.0] — 2026-10-22

### Добавлено
- Кнопка обратной связи рядом с обновлением на всех вкладках.
- Простая форма: «Проблема» или «Предложение» и текст до 1500 символов.
- Обращение сохраняется в БД и приходит администратору в бота с кнопкой
  «Ответить»; Telegram ID в тексте сообщения не передаётся.
- Ограничение от спама: не более 3 обращений за 10 минут.

### Изменено
- Экспорт и удаление персональных данных учитывают обращения через форму.

## [1.4.1] — 2026-10-22

  списка занятий тренера, не дожидаясь фоновых запросов.
- Кэшированные данные показываются мгновенно; свежие догружаются следом.
- На вкладке «Матч» список и профиль запрашиваются параллельно.
- Профиль игрока больше не задерживает показ расписания.

  «Уведомления».
- Карточка напоминания тренера и нижние панели приведены к общей сетке.

## [1.3.0] — 2026-10-22

### Добавлено
- Вкладка **«Матч»**: игроки создают отдельные игровые встречи, указывают
  время, место, уровень и число участников, присоединяются и выходят из них.
- Публичные профили игроков: нажмите на имя/аватар в расписании, матче или CRM,
  чтобы увидеть имя/животное, фото и описание.
- Бот-уведомления по тренировкам и матчам: у тренера/организатора одно
  обновляемое сообщение со списком участников, у игрока — одно сообщение
  со статусом записи. Вместо ленты сообщений используется редактирование.
- Антиспам для матчей: не более 3 публикаций за 10 минут и 30 входов/выходов
  в минуту; лимиты работают в памяти процесса.
- Лента опубликованных матчей: одно обновляемое сообщение на пользователя,
  без отдельного сообщения на каждый матч.
- Устойчивая загрузка в Telegram WebView: ожидание initData, таймаут запросов
  и кнопка повтора вместо бесконечного лоадера.
- После сохранения заметки тренера кнопка показывает «Сохранено» и снова
  активируется только после изменения текста.

## [1.2.3] — 2026-10-19

### Безопасность
- **Критично:** `/telegram/webhook` больше не принимает апдейты в `polling`-режиме.
  В `webhook`-режиме `WEBHOOK_SECRET` обязателен (≥32 символов, без placeholder),
  сравнение — в постоянном времени. Убран небезопасный placeholder из `.env.example`.
- Аватарки и `.ics` авторизуются узкими HMAC-токенами с TTL вместо полного
  `initData` в URL. Полный `initData` в query для `.ics` разрешён только при
  `ALLOW_DEV_INIT_DATA=true`.
- Обновлены зависимости с известными уязвимостями: aiogram, FastAPI, Starlette,
  aiohttp, Jinja2, python-dotenv, pydantic. `pip-audit -r requirements.txt` чист.
- CSP и security-заголовки; Tailwind CDN удалён (страницы на собственном CSS).
- Rate limiting для личных сообщений, заявок и book/cancel.
- OpenAPI (`/docs`, `/openapi.json`) выключен по умолчанию (`ENABLE_API_DOCS`).

### Добавлено
- `/readyz` — readiness с проверкой БД и Telegram Bot API; используется
  внешним healthcheck/systemd.
- Уведомления игрокам: повышение из листа ожидания, отмена тренировки тренером,
  снятие/возврат игрока; уведомление нового тренера о передаче занятия.
- CI (GitHub Actions): ruff, mypy, bandit, pip-audit, pytest.
- Изоляция тестов: чистая БД и in-memory-состояния на каждый тест.
- Экспорт и удаление персональных данных: `GET /api/me/export`,
  `DELETE /api/me?confirm=true`; документация `docs/PRIVACY.md`.
- `SECURITY.md` с порядком сообщения об уязвимостях.
- `BOT_PROXY` для HTTP/SOCKS5 и генератор Xray-конфига из VLESS-ссылки
  (`scripts/xray_vless.py`, `make xray-config`, `docs/XRAY.md`).
- Автообновление Xray-конфига из subscription URL: `scripts/update_xray_config.py`,
  systemd timer (`deploy/xray-subscription.*`), `make xray-update`; парсер
  plain/base64/JSON/HTML, атомарная запись и проверка `xray run -test`.

### Исправлено
- Повторный `POST /api/trainings/{id}/book` (двойной тап/retry) больше не
  переводит записанного игрока в лист ожидания и не меняет позицию в очереди.
- `waitlist_count` снова приходит в ответах тренера.
- Удалённые тренировки нельзя бронировать/отменять/менять/передавать.
- Отмена без записи и возврат не снятого игрока возвращают понятную ошибку;
  возврат игрока не обгоняет лист ожидания.
- `users.is_coach` синхронизируется при выдаче/снятии роли — снятый тренер
  возвращается в CRM.
- Некорректные дата/время возвращают 422, а не 500.
- Заявку нельзя отклонить после одобрения (и наоборот).
- HTML-экранирование имени в `/start` и типа тренировки в напоминаниях;
  `/inbox` разбивается на сообщения в пределах лимита Telegram.
- `.ics`: реальное число записавшихся и перенос длинных строк по RFC 5545.
- Атомарная очистка тренировки, идемпотентное добавление тренера, TTL режима
  ответа в боте, ограниченный кэш аватарок, лимиты истории/корзины.
- `make test` больше не маскирует падение тестов; добавлены `make lint/audit`.

### Удалено
- Docker-инфраструктура (`Dockerfile`, `docker-compose.yml`, `.dockerignore`) и
  Docker-команды Makefile. Деплой — Python 3.11 + `uvicorn` + systemd/Caddy или
  Render (`render.yaml`, `docs/RENDER.md`).

## [1.0.0] — 2026-10-09

Первый релиз Telegram Web App для сквош-тренировок.

### Добавлено
- Монолитный бэкенд **FastAPI + aiogram 3**, отдаёт Web App (Jinja2 + TailwindCSS) и API.
- Режим игрока: расписание на 7 дней, запись в один тап, стек аватарок участников,
  персональный тумблер пуш-уведомлений.
- Режим тренера: создание тренировок, уровень игры, напоминание в часах/минутах,
  полосы заполнения мест, список участников, CRM-заметки.
- Лист ожидания FIFO с автоповышением при отмене.
- Правило отмены: игрок не может выйти менее чем за 4.5 ч до старта (и после старта).
- Напоминания: фоновый планировщик, по умолчанию за 4.5 ч, тумблер и смещение.
- **История и корзина**: мягкое удаление тренировок, восстановление, безвозвратная
  очистка только из корзины, undo-тост.
- **Профиль тренера** (краткое описание) и **личные сообщения игрока тренеру через бота**
  с inline-кнопкой «Ответить», командами `/inbox` и `/reply`.
- **Экспорт в календарь**: `.ics` (RFC 5545, UTC, напоминание за 30 мин) и Google Календарь.
- Защита от человеческих ошибок: дубли-гард (`409` + `force`), возврат снятого игрока,
  подтверждения перед удалением.
- Мобильный UI: нижняя навигация, темы Telegram, safe-area, haptic-отклик, bottom-sheet, FAB.

### Безопасность
- HMAC-SHA256 валидация Telegram `initData` (сравнение в постоянном времени, анти-replay).
- SQLite (aiosqlite), только параметризованные запросы.
- Контейнер: непривилегированный пользователь (UID 1000), read-only ФС, `no-new-privileges`,
  `tmpfs /tmp`, нет доступа к хосту.
- Секреты только из окружения; `.env` исключён из образа и git.
- Версии зависимостей зафиксированы; отсутствуют `os.system`/`subprocess`/shell-скрипты.
- Аватарки отдаются бэкенд-прокси (токен не утекает в браузер), кэш в памяти.
- `ALLOW_DEV_INIT_DATA` (по умолчанию `false`) — послабление только для локальной разработки.

### Изменено
- Напоминание задаётся в часах и минутах; уровень игры вынесен в мета-строку карточки.
- Кнопка календаря — полноширинная, элементы карточки выровнены по правому краю.

### Инфраструктура
- Идемпотентные миграции SQLite (правило бесшовного обновления).
- `HEALTHCHECK` в образе и `docker-compose`, ротация логов, `stop_grace_period`.
- `Makefile` (build/up/logs/backup/release), `VERSION`, этот changelog.
